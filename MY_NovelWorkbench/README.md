# MY_NovelWorkbench

AI 辅助的小说创作工作台（桌面应用）：

- **节点工作流**（参考 ComfyUI）：蓝图 + 节点 + 语义连线，蓝图节点可进入（子图嵌套，上限 8 层）
- **双向链接**（参考 Obsidian）：[[wikilink]] 双链 + 全局图谱视图
- **链路驱动的 AI 上下文组装**：创作正文时，由「前后链接节点 + 上级蓝图链路」自动组装提示词，支持多 AI API（BYOK）
- **本地优先**：一本小说 = 一个目录（Markdown + JSON 纯文件真相源 + SQLite 索引缓存），天然 git 友好，随时快照回滚

## 安装

### 方式一：安装包（推荐普通用户）

下载 `MY NovelWorkbench-x.x.x-setup.exe`（Windows x64），双击安装——可选安装目录，开始菜单/桌面创建快捷方式。卸载走系统「应用」设置或自带的卸载器。

### 方式二：开发模式运行

```bash
npm install        # 安装依赖（Electron 二进制下载慢时可设 ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/）
npm run dev        # 启动开发模式（Electron 窗口 + 热更新）
```

要求：Node 20+，Windows（macOS/Linux 未做适配验证）。

## 快速上手：从零写第一章

1. **新建小说**：欢迎页点「新建小说」，选择父目录并输入书名——应用会生成标准目录结构（`novel.json` / `blueprints/` / `chapters/`）。
2. **搭蓝图**：左栏 `blueprints` 目录右键 →「新建蓝图」；进入画布后**在空白处右键**创建节点：
   - `◆ 蓝图节点`：可进入的子图（双击进入），适合「世界观 → 力量体系 → 具体设定」逐层下钻
   - `¶ 文本节点`：纯文本创作单元（提示词、文风约束写在属性面板）
   - `§ 引用节点`：指向某个章节或蓝图，承载「章节 ↔ 设定」的归属关系
3. **连语义线**：从节点端口拖出连线（默认箭头线）；选中连线可在右侧属性面板改型与备注：
   - `箭头` = 因果/顺序（展开、前后文推进）· `直线` = 并列关联 · `虚线` = 参考/伏笔
4. **打标签**：选中节点 → 属性面板选标签（内置：设定/伏笔/大纲/世界观；可新建自定义）——标签决定节点着色，也是图谱过滤与「未回收伏笔」分析的依据。
5. **写正文**：左栏 `chapters` 右键 →「新增章节」（或按卷组织：先「新增卷」再卷内加章）；**双击**章节打开编辑器，输入 `[[` 触发双链补全，引用蓝图节点。
6. **配 AI**：右侧 AI 面板 → Provider 管理 → 填 Base URL / API Key / 模型名 →「测试连接」（见下文配置示例）。
7. **AI 续写**：光标停在正文任意处，点「续写」——上下文由链路自动组装（当前章节 + 关联节点 + 上级蓝图摘要 + 前 2 章结尾），流式生成，可随时停止。

## 核心功能

### 蓝图画布

- 节点创建：**画布空白处右键**（落点即位置）；拖拽移动自动保存，`Delete` 删除选中
- 子图：双击 `◆` 蓝图节点进入，面包屑回退；嵌套上限 8 层（ADR-12）
- 跨蓝图连线：把连线拖到 `↗ 代理节点` 上即成跨图边；双击代理跳转到远端所在图
- 小地图缩放/平移；画布**视口虚拟化**（M5）——500 节点大图只渲染可见部分
- 资源库：工具条「资源库」可把常用节点/标签组存为模板，**跨小说共享**（存于应用全局目录）

### 左栏文件树

- **双击**打开文件（单击仅选中）；蓝图按父子关系呈层级，可折叠
- 目录右键：新建蓝图 / 新增卷·章节（「第N卷/第N章」中文序号自动递增）
- 章节可**拖动到另一章交换位置**（含跨卷）；重命名会自动迁移引用节点的指向
- 左下角工具：**快照**（见下）、**重建索引**（索引异常时的兜底）

### 正文编辑与双链

- Tiptap 编辑器，自动保存（600ms 防抖），Markdown 与 [[wikilink]] 双向无损往返
- `[[` 触发补全；悬浮预览目标内容；点击跳转
- **前情提要**：编辑第 N 章时自动注入前 2 章正文结尾各 800 字——AI 知道「第一章发生了什么」，无需手动关联
- 章节元信息（标题/标签/**别名**）在编辑器上方元信息区编辑；别名参与 AI 关键词兜底匹配

### AI 撰写

- **续写**：在光标处流式生成；**改写**：选中一段文字后改写（失败时原文完好）
- 生成中可**停止**；切换 Tab 自动中断进行中的生成
- **Context Viewer**：面板可查看本次实际组装的 prompt 全文、三层上下文各占多少 token、预算命中率
- 上下文组装规则：① 当前章节 + 直接关联节点全文 → ② 上级蓝图摘要卡（50-100 字/层）→ ③ 深层节点按边语义加权（箭头 > 直线 > 虚线）；预算分层 60/25/15，未满时按正文关键词（含别名）兜底

### 全局图谱

- 左侧图标条「图谱」进入：全部小说节点/边投影为一张力导向图
- 按标签着色与勾选过滤；点击节点跳转到所在蓝图并选中
- 分析开关：**孤立节点**（没有任何链接）与**未回收伏笔**高亮提示（红色 ! 角标）

### 快照（M5）

- 左栏「快照」按钮：把当前小说完整拷贝到 `<小说目录>/.snapshots/`（排除 `.git` 与索引缓存）
- **恢复**前自动创建「恢复前自动备份」快照——误恢复也能退回来
- 最多保留 10 份（超出自动清最旧）；快照不进文件树、不触发索引重建

## AI Provider 配置（BYOK）

应用自带 Provider 层，任何 OpenAI 兼容接口均可（自建网关/one-api 同理）：

| 厂商 | Base URL | 模型示例 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4.6` |
| Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-32k` |
| Ollama 本地 | `http://localhost:11434/v1` | `qwen2.5:14b` |

- 可配置多个 Provider，随时切换；API Key 经系统密钥链（safeStorage）加密存储，**不明文落盘、不回传界面**
- 「测试连接」会真实请求 `/models` 验证

## 数据与隐私

一本小说 = 一个目录，全部是纯文本：

```
我的小说/
├── novel.json               # 书名/标签库
├── blueprints/*.blueprint.json   # 蓝图（节点/连线）
├── chapters/                # 正文（Markdown + frontmatter，支持一层卷目录）
│   ├── 第01章.md
│   └── 第一卷/第02章.md
├── .index/                  # SQLite 索引缓存（可删，打开时自动增量重建）
└── .snapshots/              # 快照（最多 10 份）
```

- 数据不出本机：AI 请求只发给你自己配置的 API；API Key 加密存于 `%APPDATA%/my-novel-workbench/`
- 对小说目录 `git init` 即可获得版本管理（快照是应用内的轻量替代）
- 性能参考（M5 实测）：10 万字小说冷启动索引 **60ms**（增量打开近零开销）；500 节点画布视口虚拟化渲染

## 故障排查

| 现象 | 处理 |
|---|---|
| 文件树/图谱数据不对 | 左栏「重建索引」 |
| AI 连接测试失败 | 检查 Base URL 是否带 `/v1`（各家不一）、Key 是否有效、本机能否访问该域名 |
| Electron 下载慢/失败 | `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm install` |
| 打包时二进制下载超时 | `ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/ npm run dist:win` |
| 误恢复快照 | 快照面板里找「恢复前自动备份」再恢复回去 |

```bash

node scripts/gen-stress-blueprint.mjs <小说目录> [节点数] [--chapters N --words 每章字数]
                    # 压力样本：大画布 + 长章节性能测试
npm run gen:icon    # 重新生成应用图标（build/icon.ico）
```
